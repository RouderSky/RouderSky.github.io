C++ Primer 第1章：从第一个程序理解输入输出

C++ 程序从哪里开始执行，输入的数据怎样进入变量，结果又怎样显示到终端？这些问题看起来基础，但后面调试输入错误、输出顺序、日志丢失时，最后往往仍要回到这一章。

下面从一个可以真正运行的例子开始。

一个最小的 C++ 程序

这段程序包含几个不可缺少的部分。

#include <iostream> 是预处理指令。它在编译前把标准输入输出库的声明引入当前源文件。没有这一行，编译器不知道 std::cout 和 std::endl 是什么。

int main() 是程序入口。操作系统启动程序后，会从这里开始执行。标准 C++ 的 main 返回 int，return 0 表示程序正常结束，非零返回值通常表示出现了错误。

std::cout 是标准输出流。std:: 表示 cout 位于标准命名空间 std 中。命名空间用于隔离名字，避免不同库中的同名函数或对象互相冲突。日常小练习常用 using namespace std;，但在头文件和较大的项目中直接展开整个命名空间，容易引入难以发现的名称冲突。

四个标准流

标准库提供了四个常用流对象：

  • std::cin：标准输入，类型为 istream。
  • std::cout：标准输出，类型为 ostream。
  • std::cerr：标准错误，类型为 ostream，通常不缓冲。
  • std::clog：标准错误日志，类型为 ostream，通常会缓冲。

cout 用于正常结果，cerr 和 clog 用于错误与诊断。它们默认都可能显示在同一个终端里，但用途不同。

把正常结果和错误信息分开，有一个实际好处：运行时可以把两者分别重定向到不同文件。例如正常运行日志写到 output.txt，错误信息仍显示在终端。

cerr 通常不缓冲，所以错误发生时会尽快出现。clog 使用缓冲，适合普通日志。不要把 cerr 当成第二个 cout，否则以后排查错误时会缺少一条清晰的分界线。

缓冲区解决什么问题

设备读写通常比内存操作慢。如果每输出一个字符都立即访问终端，代价会很高。流因此会先把数据放进缓冲区，再在合适的时候批量交给输出设备。

缓冲区会带来一些看似奇怪的现象：

  • 程序已经执行了输出语句，终端却暂时没有显示。
  • 程序崩溃后，最后几条普通输出可能丢失。
  • 错误信息使用 cerr 时，反而比之前的 cout 先出现。

这些现象不说明输出语句没有执行，而是数据还没有从缓冲区送出去。

std::cin 和 std::cout 默认绑定在一起。程序从 cin 读取前，会先刷新 cout，所以交互式程序的提示信息通常能及时显示。

文件结束符

文件结束表示输入源没有更多数据，不是输出格式。

在交互式终端中：

  • Windows 常用 Ctrl+Z 产生文件结束状态。
  • Unix、Linux 和 macOS 常用 Ctrl+D。

读取失败和文件结束都会让输入流进入不可用状态。可以用 std::cin.eof() 检查是否遇到文件结束，用 std::cin.fail() 检查读取是否失败。实际代码里，直接判断 if (std::cin >> value) 往往更简单。
