我所理解的C++ 03-3｜数组名什么时候会退化成指针

本文最后更新于：2026年11月24日 晚上

先看一个经常被写进“通用数组工具函数”的例子：

在常见的 64 位平台上，第一行输出 4，第二行却输出 2。这并不是编译器算错了，而是 values 在两处具有不同的类型。

在 main 中，values 是包含四个 int 的数组对象。传给 array_size 时，它转换成指向首元素的 int*。函数参数写成 int values[] 只保留了“可以像数组一样使用”的外观，实际类型仍然是指针。

所以函数里的 sizeof(values) 得到的是一个指针的大小，sizeof(values[0]) 得到的是一个 int 的大小。两个数相除，自然不再是元素个数。

“数组名会退化成指针”这句话经常被当作固定规则记住。更准确的说法是：数组在大多数值表达式中会执行数组到指针的转换，但有些上下文必须保留数组本身的类型。分不清这两种情况，就会出现看似能用、换一个位置就失效的代码。

这里的 first 保存的是 &values[0]，类型为 int*。指针本身只知道一个地址，不知道它后面究竟有四个、十个还是一个元素。

这也是为什么数组不能整体赋值：

赋值表达式需要右侧的值转换成左侧可接收的类型。数组会转换成指针，而数组本身又不能作为赋值目标，所以这不会变成“复制三个元素”。

也可以让函数接收数组引用，使长度进入参数类型：

二维数组并不是“一个带两个下标的特殊指针”，而是元素本身也是数组的数组：

如果使用数组引用或模板，可以把第一维长度也保留下来，但接口就会限定为精确的数组类型。实际代码中应根据调用场景选择，不要把数组引用当成所有参数的统一替代品。

std::begin 和 std::size 也依赖数组类型

标准库提供了不手写 sizeof 除法的工具：

对数组使用 std::begin 和 std::end 时，模板参数仍能看见完整的数组类型。C++17 的 std::size 直接返回元素数量。

但如果数组已经传给指针参数，这些工具就拿不到长度：

这不是标准库“不支持数组”，而是函数里根本没有数组对象了。values 已经是 int*，无法从地址恢复原始的数组边界。

因此，一个稳妥的设计原则是：在数组类型仍然完整的调用处取得长度，再把起始地址和长度一起传给下层函数。

这样，需要指针和长度的底层实现保持通用，数组的边界则在能够看到数组类型的地方确定。

最后的检查点

  • 函数参数写成 int values[4] 时，是否误以为 4 会在运行时检查长度？
  • 在函数内部对参数使用 sizeof(values) / sizeof(values[0]) 时，是否还在计算数组元素个数？
  • 需要完整数组类型时，是否考虑了数组引用或模板参数 N？
  • auto values2 = values 是否把数组转换成了指针？
  • 对多维数组做范围 for 时，外层循环变量是否使用了引用？
  • 已经退化成指针的变量，是否还被交给了 std::size、std::begin 或依赖数组边界的模板？
  • 计算指针偏移前，是否确认了目标元素仍位于同一个有效数组范围内？

数组到指针转换本身不是错误，它是 C 和 C++ 接口能够共享连续内存的基础。真正需要警惕的是把转换后的指针误当成“仍然携带长度信息的数组”。
